master's capstone · ML security

Sybil-Resilient Model Extraction Detection

An extension of PRADA (Juuti et al., EuroS&P 2019), tested on an MNIST classifier. My master's capstone at Rutgers.

The problem
PRADA spots model-stealing by checking whether an account's query distances look normally distributed. An attacker can split queries across fake (Sybil) accounts so each one stays under PRADA's 100-query warm-up and never gets checked.
What I built
A second detection layer that compares query-distance histograms across accounts using Jensen-Shannon divergence. Sybil accounts all send Jacobian-generated images, so their histograms converge. Benign accounts' don't.
Result
PRADA alone flagged 0 of 64 Sybil accounts. With the JS layer, detection held from 4 to 128 accounts with zero false positives.
0 / 64Sybil accounts caught by PRADA alone
0false positives, 4 to 128 accounts
0.9978pair-level AUC, 64 Sybil vs 64 benign
96.56%attacker's substitute model agreement
  • Python
  • FastAPI
  • JS divergence
  • MNIST
View code on GitHub

What I'd recommend

Run a cross-account check like this alongside per-account detection on any public model API, and re-tune the threshold on held-out traffic before relying on it in production.

How the test bed works

A CNN victim model (99.08% MNIST test accuracy) is served through a FastAPI endpoint that logs every query. A Papernot Jacobian-based attack runs 6 augmentation rounds to train a substitute model. PRADA (distance computation plus a Shapiro-Wilk test) and the JS layer are evaluated side by side, including a benign-user baseline and three query distributions: round-robin, randomized, and mixed 70/30.

What it can't do

  • Beyond about 192 Sybil accounts, per-account histograms get sparse and the JS separation gap collapses, so detection becomes unstable.
  • A mixed 70/30 attack shrinks the separation gap to 0.002 in some configurations. Still detected, but the margin is thin.
  • The JS threshold (0.15) was tuned on the same data used for evaluation. There is no held-out test set.
  • PRADA's AUC of 1.0 comes from only two W scores, so I don't treat it as a robust result.

SQL + Power BI

Olist Delivery Performance

99,441 Brazilian e-commerce orders across 27 states and 70+ product categories.

The question
Which product categories and regions have the highest late-delivery rates, and does that line up with lower review scores? Written for two audiences: Logistics and Customer Experience.
What I did
Joined the orders, customers, products, sellers and reviews tables in PostgreSQL. Flagged late orders with CASE WHEN, ranked states and categories with RANK() OVER, dropped categories under 500 orders to cut small-sample noise, and exposed SQL views as the data layer for a four-visual Power BI dashboard.
Result
Alagoas had the worst late rate at 23.0% of orders. Electronics led categories at 9.6%. Late delivery and review score showed a moderate negative correlation of -0.327.
99,441orders analyzed
23.0%late rate in Alagoas, the worst state
9.6%late rate for electronics, the worst category
-0.327correlation, late delivery vs review score
  • PostgreSQL
  • RANK() OVER
  • CORR()
  • Power BI
View code on GitHub

What I'd recommend

Start with Alagoas and the electronics category, where late rates are highest. Since late orders track with lower review scores, add seller and carrier data next to find out why those orders run late.

Limits

This locates where delivery problems are worst. It doesn't claim a root cause, because seller, warehouse and carrier data aren't in the dataset. The worst-category-per-state ranking is only reliable for the five high-volume states: MG, PR, RJ, RS and SP.

SQL + DAX

F1 Pit Stop Strategy

10,884 Formula 1 pit stops from 2011 to 2024, across six PostgreSQL tables.

The question
Does pit stop speed relate to where a driver finishes, and have stops gotten faster over the years?
What I did
Tested the link at three levels (single stop, race average, race total) with CORR(), compared constructors with AVG and STDDEV, and tracked year-over-year change with LAG. In Power BI I rebuilt the Pearson correlation by hand in DAX and matched SQL's 0.175.
Result
The link is weak: +0.135 to +0.175. P1 finishers averaged 43.2s of pit lane time per race vs 57.0s for P18, but top teams tend to have both faster cars and faster crews, so pit speed alone doesn't explain results.
10,884pit stops analyzed
+0.175strongest correlation, race total
+1.29sbiggest year-over-year change in average pit time, 2013 to 2014
23.74sRed Bull average pit time, fastest and most consistent
  • PostgreSQL
  • LAG()
  • Power BI
  • DAX
View code on GitHub

What I'd recommend

Don't treat pit-crew speed alone as a lever for race results. The bigger gap between teams is consistency: Aston Martin is mid-pack on speed but second-worst on variability, so that is where a team would focus.

Data cleaning

Stops of 100 seconds or longer were filtered out as red-flag and safety-car artifacts, so they wouldn't distort the averages.

NFL Performance & Weather

25 NFL seasons (2000 to 2024) joined with historical weather data. A course project built with two classmates.

The question
Sports talk says warm-weather teams struggle in the cold and cold-weather teams struggle in the heat. Does the data agree, in both directions?
What we did
Built an ingestion script for game data with nflreadpy and a weather-enrichment step with the Meteostat API, then compared road win rates across temperature thresholds in a notebook.
Result
Warm-weather teams' road win rate drops 7.7 points in extreme cold. Cold-weather teams show no drop in heat (+3.4 points). The myth only holds one way.

What I'd recommend

For warm-weather teams, cold road games are where results drop, so that is where extra preparation pays off. Cold-weather teams don't need to treat heat as a special risk.

machine learning · bioinformatics

EvoStruct-Sub Protein Localization

523 Gram-positive bacterial proteins, four subcellular locations.

The question
Given only a protein's amino-acid sequence, can a model predict which of four locations it belongs to: cell membrane, cell wall, cytoplasm or extracellular?
What I did
Combined evolutionary features from PSI-BLAST (PSSM) with structural features from SPIDER 2.0 into a 405-feature matrix, then trained and compared KNN, SVM and Random Forest.
Result
Random Forest reached 99.23% accuracy, well ahead of SVM (79.08%) and KNN (77.74%). That gap is unusually large for 523 samples, so I treat it as a result to verify, not a final number.
523proteins
405features per protein
99.23%Random Forest accuracy
79.08%SVM accuracy
  • Python
  • Scikit-learn
  • PSI-BLAST
  • SPIDER 2.0
View code on GitHub

What I'd recommend

Use Random Forest on the combined evolutionary and structural features as the starting model, and confirm the result with stratified cross-validation before using it on new proteins.

Reproducibility

Pre-extracted features and trained models are in the repo, so the classifiers run in about 10 minutes without the external tools. Rebuilding features from raw sequences needs PSI-BLAST and SPIDER 2.0 and takes several hours.

Metaheuristic Algorithm Comparison

Breast cancer classification on the UCI dataset.

The question
Instead of gradient descent, how well do metaheuristic optimizers train a classifier, and which one generalizes best?
What I did
Implemented and compared the Grasshopper Optimization Algorithm, Wolf Pack Optimization, Particle Swarm Optimization and a Genetic Algorithm, tracking train and test accuracy and loss for each.
Result
Wolf Pack and PSO tied at 97.37% test accuracy, the Genetic Algorithm reached 96.49%, and Grasshopper lagged at 71.05%.
